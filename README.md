## What I've built

### Construction cost estimator
Pre-construction budgets for multifamily and mixed-use used to take weeks and arrive un-auditable. This reads a plan-set PDF, extracts quantities by CSI division with Claude, prices them against a deterministic RSMeans New Jersey cost database, and produces the estimate workbook, bid leveling, gap analysis, RFI letters and a negotiation brief. The AI measures; it never prices.
`Python` `Anthropic API` `Excel`

### Portfolio intelligence dashboard
Daily oversight of 50+ properties and 7,000+ units from one screen. Exception-based focus list (critical, high, watch) with the dollar exposure and the recommended action on each item, and unit-level drill-down for vacancy, renewals, delinquency, work orders and evictions. Built for the morning operations call.
`React` `Vercel` `AppFolio API`

### Operations audit of a 7,000-unit manager
One year of property-management audit log, 782,000 logged actions, crossed against the platform's own feature set. Found 21 manual patterns costing about 4,580 staff hours a year, ranked the fixes, and separated what the current software tier already does from what needs an upgrade.
`Python` `Excel` `PDF`

### Entitlement tracking
Ask three people where a development project stands in approvals and you get three honest, different answers. I replaced the status report with 32 ordered gates, from site control through certified resolutions and permits, each closed only by a specific document a third party holds: a signed resolution, a recorded instrument, an issued permit. A project's position is the furthest gate whose closing artifact can be produced on request. No percentages, no judgement calls, and a missing document is the finding, not a system failure.
`Process design` `Reporting`

### Investor CRM for equity raises
Relationship management for the equity side of development deals: investors, commitments, communications and follow-ups in one place instead of spreadsheets and inboxes.
`Next.js` `TypeScript` `PostgreSQL`

### MyTradeMentor: risk discipline for my own portfolio
A rules-based system for the sell side of my own account. Every share sits under a stop, every exit rule is named and logged before the outcome is known, and the system can only sell, never buy; I approve each order by hand. Built because the discipline that protects a real estate portfolio should protect a securities portfolio too.
`Python` `Flask` `Brokerage API`

### CRE skills library
A structured library of 105 commercial real estate skills and 55 specialist agents for underwriting, deal screening, leasing, due diligence, development, asset management and disposition, written so an AI assistant follows the same process a seasoned analyst would.
`Claude Code` `Markdown` `YAML`

## How I work

- **Measure state, not activity.** A task list tells you what people are doing. It never tells you where the project is.
- **A document in hand beats a status report.** If the proof can't be produced, that is the finding.
- **Thin glue on the systems the team already lives in.** Don't replace the platform; wire it to where the work happens.
- **Start with the end user.** If the person doing the work every day won't use it, it doesn't matter how good it is.
- **Guard rails before upside.** Every system we build limits the downside first.
